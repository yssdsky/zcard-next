# ZCard v1.2.114

发布日期：2026-11-01

## 完整卡密导入与交付

- 修复普通卡密含 `---`、`----` 等分隔符时被当作靓号格式，只保存并交付首段的问题。默认每个非空行的完整内容作为一条卡密；预览、去重、加密保存、导出与按规格交付使用同一份内容。
- 相同序列号、不同激活码的完整卡密不再被错误判为重复；多规格库存继续分别预留和交付，重复取货保留原完整内容。
- 靓号号码导入改为明确选择的模式，仅取 `---` 前的号码，后续字段不作为交付内容，价格与备注不导入；默认完整行模式不会再根据分隔符自动切换。

## 后台查看与修正卡密

- 库存页面增加显式查看完整卡密入口，按独立权限及安全审计处理；普通列表继续只返回掩码。
- 可修正未使用且未被预占、会员锁定、发奖或订单引用的库存卡密。保存保留原商品、规格和导入批次，重新加密并核对重复和并发版本；已售卡密及历史交付记录不能借此改写。
- 明文只在查看或编辑窗口中显示，关闭后清理；敏感接口禁止缓存，运行日志和操作审计不保存卡密正文。

## 订单邮件与游客邮箱查单

- 修复普通虚拟商品游客订单申请邮箱验证码时返回成功却没有发送的问题。下单邮箱验证成功后，可用仅对应当前订单和站点的凭证查询及取货；原查询密码继续可用。
- 补齐订单邮件的收件人解析和默认通知模板，发送付款及发货通知和安全查单/取货链接；商户已配置的模板和明确停用状态继续生效。
- 邮件中不放卡密或查询密码；完整卡密通过受保护的取货页面查看。验证码仍受有效期、冷却时间、尝试次数和一次性消费限制。
- 邮箱发送需要正确配置 SMTP。配置缺失或发送失败会给出可核对的状态，不代表真实邮箱服务已完成投递验收。

## 验证范围

后端全量测试、go vet、库存/订单/履约/通知/支付竞态检测、真实隔离 MySQL / PostgreSQL 集成测试、前后台类型检查与生产构建、翻译检查和 fullstack 嵌入资源测试已通过。桌面及手机浏览器回归覆盖完整卡密查看和修正、权限和状态限制、导入格式切换、游客邮箱验证码查询及完整卡密展示与复制。

本地真实 SMTP 连接验证了中英文付款/发货通知、普通虚拟游客验证码、模板自定义和停用状态，以及发送失败反馈。相关回归覆盖大整数订单标识、验证码一次性消费、跨站点和跨订单隔离、原查询密码兼容、支付重试及未付款时不返回卡密。

## 升级与历史数据

请先备份数据库、配置和上传文件，保留原加密密钥，配套更新服务端、后台和内置商城并重启、刷新页面。本版无新增数据库迁移，不需要重新创建商品或规格。

旧版本已经截断保存的卡密后半段没有保存在卡密、导入批次或审计记录中，升级无法自动还原。请用原导入文件或供应方原始记录补正未使用库存；也可禁用旧卡后重新导入完整卡密，避免旧错误卡继续出售。已售订单请按原始记录联系买家补齐，历史交付不会自动改写。

频道公告由用户手动发送。版本发布不代表客户生产站点已自动升级。
